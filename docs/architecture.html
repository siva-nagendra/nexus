Layer 1: In-Game HTTP Server Game Thread <1ms

Replaces TCP background thread with UE5's FHttpServerModule. Route handlers execute directly on the game thread during Tick(). Zero dispatch overhead, zero polling. Port 13378.

UNexusHttpSubsystem : UGameInstanceSubsystem

Layer 2: Native Scene State Per-Frame

Cached FNexusSceneState struct updated every frame in Tick(). Pipeline state, mode, segments, camera, actors, depth info. Handlers and agents read this instead of querying GameMode each call.

Layer 3: Parallel Agent Pool Concurrent

Multiple FNexusAgentWorker instances run concurrently via independent FTimerHandle callbacks. Game-thread ops execute in timer callbacks; ML inference dispatches to AsyncTask(AnyBackgroundThread) with game-thread completion callbacks. Up to 5 concurrent agents. OODA loop: Observe (cached state) > Decide (goal planning) > Act (dispatcher call) > Evaluate (pre/post diff).

Layer 4: Activity Panel Glassmorphism

Slate widget matching SceneForge's design. Live command stream with latency badges, per-agent status cards with progress bars, memory/learning indicators. Toggle via N hotkey or brain icon.

Layer 5: Call Logging RL Data

Every command logged to ~/.nexus/memory/calls/YYYY-MM-DD.jsonl. Unified format across C++ and Python paths. Command, params, response, timing, success/failure. Training dataset for reinforcement learning.

Architecture Options

Three approaches considered for the in-game command server

Option A: FHttpServerModule

UE5's built-in HTTP server. Ticker-based, game-thread native. Route handlers execute during Tick(). Used by UE5's own ExternalRpcRegistry.
+ Zero dispatch latency (same frame response)
+ Zero background threads needed
+ HTTP semantics (clean req/res, no TCP fragility)
+ Multi-client support (no connection queuing)
+ Proven in production (ExternalRpcRegistry)
- HTTP parsing overhead (~0.1ms per request)
- New port (13378) during transition period
- Requires HTTPServer module in Build.cs

Option B: Fix TCP Threading

Keep existing TCP server but make it multi-threaded (one thread per connection) and add non-blocking game thread dispatch with event-driven completion.
+ No port change needed
+ Fully backward compatible immediately
+ Binary protocol (slightly less overhead)
- Still pays cross-thread dispatch cost
- More threading complexity (race conditions)
- Idle timeout problem persists per-thread
- No standard request/response semantics

Option C: Shared Memory IPC

No network at all. Python pushes to a shared memory queue, C++ drains it every frame via FCoreDelegates::OnBeginFrame. Absolute minimum latency.
+ Literally same-frame (sub-microsecond)
+ No network stack at all
+ No port conflicts
- Complex shared memory setup (platform-specific)
- Python and C++ must agree on memory layout
- Debugging is much harder (no HTTP tools)
- No external access (only co-process Python)

Risks and Gaps Identified

Issues discovered during research that the implementation must address

Agent Conflict on Shared Actors HIGH

Two parallel agents can move the same actor simultaneously. The second write silently wins, producing unpredictable placement.

Mitigation: Resource locking via TSet<FString> LockedActorPaths per agent worker. Lock acquired before Acting, released after Evaluating.

Unbounded Memory Growth HIGH

JSONL call logs append forever. After heavy use, daily files can reach 100MB+. No archival, compaction, or TTL exists.

Mitigation: Log rotation (keep 30 days, gzip older). Max file size 50MB with rollover. Summarize old entries into aggregate stats.

Stale Ground Plane During Scene Build MEDIUM

RANSAC ground detection runs once at pipeline start. As objects are placed, the depth-derived ground plane becomes stale, causing drift in later object placement.

Mitigation: Re-run /detect-scene-surfaces after every 3 objects placed. Agent evaluator checks ground consistency.

Segment Deduplication Missing MEDIUM

The /check-overlap MLServer endpoint exists but is not wired into the agent loop. Re-segmenting the same area creates duplicate meshes.

Mitigation: Agent calls /check-overlap before accept_segment. Overlap threshold 0.7 triggers skip.

MaxConcurrentConversions Not Agent-Aware MEDIUM

The UI setting limits parallel conversions, but agents can bypass it by calling convert_all directly. No coordination between agents and the pipeline's own concurrency limiter.

Mitigation: Agent reads USceneForgeSettings::MaxConcurrentConversions before dispatching. Shared ActiveConversionCount across agent pool.

VLM Refinement Capped at 3 Iterations LOW

The existing refinement loop maxes at 3 iterations. Complex scenes may need more passes. With parallel agents, refinement can run continuously.

Mitigation: Dedicated refine_placement agent with configurable iteration limit (default 10). Runs alongside the conversion pipeline.

GameMode Null During Subsystem Init LOW

UGameInstanceSubsystem::Initialize() runs before the GameMode spawns. Scene state cache and agent subsystem must handle null GameMode gracefully.

Mitigation: Null checks in Tick() and AgentTick(). Return default empty state. Agent stays Idle until GameMode is valid.

FHttpServerModule Availability in -game Mode LOW

FHttpServerModule is a Runtime module (not Editor-only), but its behavior in standalone -game builds may differ from Editor PIE. Needs validation.

Mitigation: Test on first build. Fallback: keep TCP server alongside HTTP server for transition.

Feature Roadmap

Prioritized features based on whole-scene pipeline analysis (from Engram vault)

PriorityFeatureWhyHow
P0 Local Grounding DINO Agent Remove Gemini API latency (3-5s) for re-scans. Local detection at ~200ms. Agent calls /detect-objects-local with cached GDINO prompt. No API key needed.
P0 Failure Recovery with Provider Fallback Meshy failures block the pipeline. Auto-retry with Tripo3D or Rodin unblocks it. Agent tracks provider failure rates in memory. On failure, retries with next-best provider.
P0 Auto-Quality Scaling by Object Importance Large foreground objects need High quality, small background objects need Simple. Saves API cost and time. Agent reads segment area + depth. Large foreground = High, medium = Medium, small/background = Simple.
P1 Continuous VLM Refinement Agent Current 3-iteration cap is insufficient for complex scenes. Dedicated agent refines placement continuously. Separate agent with goal refine_placement starts after first 3 objects placed. Runs alongside generation.
P1 Depth-Adaptive Ground Plane Refresh Stale RANSAC ground plane causes drift as objects accumulate. Need periodic re-detection. Agent triggers /detect-scene-surfaces every 3 placed meshes. Updates ground_plane_y for subsequent objects.
P1 Scene Version Snapshots No rollback if agent makes bad decisions. Need checkpoints at each pipeline stage. Auto-save session at: post-detection, post-segmentation, post-conversion. Named: {session}_step{N}.
P1 Streaming Object Appearance Users see empty scene until all objects convert. Each mesh should appear as it completes. Already implemented (parallel conversion). Agent broadcasts progress events to activity panel per-object.
P1 Overlap Deduplication Re-segmenting the same area creates duplicate meshes. Wastes API calls and clutters scene. Agent calls /check-overlap before accept_segment. Overlap > 0.7 triggers skip.
P2 Agent Memory Priming Agents start cold each session. Past successes/failures should inform first decisions. On StartGoal(), recall top-20 entries from ~/.nexus/memory/{goal_type}.jsonl. Bias planner toward successful patterns.
P2 Multi-View Scene Evaluation Single-viewpoint screenshot misses back/side placement issues. Need 4-view comparison. Agent captures 4 screenshots (front, left, right, top-down) via set_camera, sends all to VLM for holistic evaluation.
P2 Material/Lighting Co-Agent Meshes arrive with baked textures. Scene lighting often clashes with material colors. Dedicated agent analyzes image color palette, adjusts directional light color temperature and intensity to match reference mood.
P2 RL Training Pipeline Call logs accumulate but are never used for learning. Need offline RL processing. Python script reads JSONL, extracts (state, action, reward) tuples. Reward = visual_score improvement. Train policy model for agent planner.

Whole-Scene Generation Pipeline

From vault: complete flow with endpoints, timing, and parallelism

1

Object Detection (Gemini 2.5 Flash)

Vision model identifies all objects with labels, normalized bounding boxes, and foreground/background classification. Structured JSON output via responseMimeType.

POST /detect-objects POST /detect-objects-local (Grounding DINO fallback)
~3-5s (API) | ~200ms (local GDINO)
2

Batch Segmentation + Scene Shell PARALLEL

2a: SAM 2.1 box-prompt segmentation for all detected foreground objects. Returns masks, bboxes, centroids, areas.
2b: Open3D Poisson reconstruction from 16-bit depth + color to GLB scene shell mesh. Both run simultaneously.

POST /segment-batch POST /depth-to-mesh
~1-3s (parallel)
3

3D BBox Lifting + Surface Detection

Compute full 3D bounding boxes from depth + masks (center, dimensions, ground contact, yaw via PCA). RANSAC plane fitting detects ground/walls/ceiling for clean geometry.

POST /lift-to-3d-bbox POST /detect-scene-surfaces
~500ms
4

Parallel 3D Conversion UP TO 5 CONCURRENT

Each segment: crop masked region, send to Meshy/Tripo3D/Rodin, poll for completion, download GLB, import via glTFRuntime, scale to 3D bbox, place at deprojected position. Managed by TMap<FString, FTimerHandle> ParallelPollTimers.

POST /convert-to-3d GET /{provider}-status/{id}
30-120s per object | 5 concurrent = 5-10x speedup
5

VLM Refinement Loop (Gemini Vision)

Capture scene screenshot, compare side-by-side with target image. Gemini returns per-actor delta adjustments (position, yaw, scale). Iterate up to 3x (configurable).

POST /refine-placement
~5s per iteration | 3 iterations default
6

Finalize Scene

Auto-hide 2D reference image, switch to Explore mode. Scene ready for WASD flythrough inspection. Session auto-saved.
